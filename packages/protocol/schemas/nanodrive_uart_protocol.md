# NanoDrive UART 协议

版本 v0.9 · 115200 8N1 · 每条消息以 `\n` 结束

## 当前连接边界

当前运行路径使用 BLE 透明串口传输 v0.9 行协议。StackChan 不与 NanoDrive 直接接 UART 线，也不订阅底座回传；NanoDrive 的回复仍可通过 USB 单机诊断查看。

## 传输变体

正式运行变体：

```text
StackChan BLE Central
  -> JDY-23A/BK3432 GATT service FFE0 / write characteristic FFE1
  -> 模块 UART 115200 8N1
  -> NanoDrive UART1
  -> NanoDrive v0.9 固件（EN / VL / ST 等换行指令）
```

StackChan 使用 FFE1 无响应写入。首次运动或急停后，将 `EN:1` 与首条运动命令合并在同一个 BLE 包内；后续直接发送 `VL:left,right`。停止发送 `ST`，遥控器输入按 250 ms 刷新，底座 2000 ms 看门狗兜底。

商家 `A/E/Z/H/B/G/C/F/D` 单字符固件只保留为 A4950 电机方向和蓝牙透传的基准验证，不再作为正式运行协议。

当前 BLE 应用层仍是单向控制：StackChan 只能确认 FFE1 写入请求已接受，不能把它表述为 NanoDrive 回执。协议保留返回消息，供 USB 单机测试和未来增加 BLE 通知后使用。

## 指令

| 指令 | 参数 | 作用 |
|---|---|---|
| `PING` | 无 | 返回固件版本 |
| `EN` | `0` / `1` | 禁用或使能；`EN:1` 同时解除急停 |
| `FW` / `BW` | `0..255` | 前进 / 后退 |
| `TL` / `TR` | `0..255` | 原地左转 / 右转 |
| `VL` | `left,right`，各 `-255..255` | 左右轮差速 |
| `ST` | 无 | 立即停止并进入急停状态 |
| `GS` | 无 | 查询编码器、电池和安全状态 |
| `TO` | `0..10000` ms | 设置运动超时，`0` 为关闭 |
| `RS` | 无 | 清零编码器 |
| `DI` | 无 | 查询左右编码器中断是否触发过 |

## 返回

| 返回 | 含义 |
|---|---|
| `OK:PONG:v0.9` | 连接和版本正常 |
| `OK:EN:n` / `OK:ST` / `OK:TO:n` / `OK:RS:0` | 指令已执行 |
| `ST:L123,R456,V7680,E0,M1` | 左右编码器、电池 mV、急停、运动中 |
| `DI:L1,R1` | 左右编码器中断均触发过 |
| `ERR:DISABLED` | 电机未使能 |
| `ERR:ESTOP` | 急停后尚未重新 `EN:1` |
| `ERR:TIMEOUT` | 运动指令超过看门狗时间，已停车 |
| `ERR:FORMAT` / `ERR:UNKNOWN` | 格式或指令错误 |

## 安全约束

- 上电默认禁用且停止。
- 当前看门狗为 2000 ms，只在运动期间计时。
- `ST` 后必须再次发送 `EN:1` 才能运动。
- StackChan 对外动作默认限制速度为 `0..180`，NanoDrive 固件仍接受 `0..255`。
- 编码器当前在 A 相 `CHANGE` 中断计数，实际里程换算需实机标定，不在本协议中预设倍频、轮径或减速比。
