# 开发者接入指南

屿见面向应用开发者、Agent 开发者、智能眼镜厂商、机器人厂商与内容创作者提供统一扩展方式。新增设备或能力时，只需实现相应模块并声明能力，无需修改 Agent 核心。

## 可以开发什么

| 模块类型 | 作用 | 典型示例 |
| --- | --- | --- |
| 感知模块 | 将外部信息转成 Agent 可理解的上下文 | 语音、视觉、通知、位置、设备传感器 |
| Agent 能力模块 | 扩展规划、记忆、人格与主动行为 | 日程策略、陪伴人格、情境提醒 |
| 工具模块 | 连接软件服务并返回结构化结果 | 待办、天气、新闻、智能家居 |
| 体验模块 | 组合规则、内容、界面和多端表现 | 陪伴、农场、游戏、工作模式 |
| 硬件适配器 | 将统一语义动作转换为设备指令 | 表情、灯光、声音、转头、移动 |

## 模块生命周期

```text
创建模块 → 声明能力与权限 → 注册工具或动作
         → 加载并发现 → Agent 调用 → 返回结果 → 更新或卸载
```

模块应保持职责单一：Agent 负责理解、规划和决策，模块负责完成明确能力并报告结果。模块不得假定调用一定成功，也不应把设备协议或品牌差异写入 Agent 核心。

## 推荐目录

```text
my-module/
├─ manifest.yaml
├─ README.md
├─ src/
├─ assets/
├─ examples/
└─ tests/
```

`README.md` 应说明用途、权限、依赖、接入方式和最小示例；运行时生成内容、密钥和个人数据不得进入仓库。

## 模块清单

`manifest.yaml` 用于描述模块如何被系统发现和使用。概念字段如下，具体结构以公共协议包为准：

```yaml
id: com.example.my-module
name: My Module
version: 1.0.0
capabilities: []
tools: []
permissions: []
ui_slots: []
hardware_requirements: []
dependencies: []
```

- `capabilities`：模块提供的语义能力。
- `tools`：可供 Agent 调用的工具及输入、输出和错误定义。
- `permissions`：摄像头、通知、位置、设备控制等授权要求。
- `ui_slots`：App 或眼镜中的页面、卡片、按钮和设置入口。
- `hardware_requirements`：所需传感器、显示或执行能力。
- `dependencies`：其他模块、服务或最低兼容版本。

## 接入软件工具

软件工具适合连接日程、待办、天气、内容服务和智能家居。一个可用工具至少应定义：

1. 清晰、稳定的语义名称；
2. 可校验的输入和结构化输出；
3. 权限、超时、取消与错误状态；
4. 幂等性或重复执行规则；
5. 可供 Agent 判断任务是否完成的执行结果。

工具可通过 MCP 等标准能力接口注册到能力中心。Agent 依据用户目标和当前上下文选择工具，能力中心负责发现、权限检查与调用路由。

## 创建体验模块

体验模块将工具、内容、状态和多端表现组合成完整场景。建议声明：

- 进入条件、主动触发条件与冷却规则；
- 需要读取和写入的状态；
- 可调用的工具和硬件语义动作；
- 正式回复、内心 OS、通知、音效和实体表现的分工；
- 用户可调整的强度、频率和权限；
- 退出、暂停与异常降级方式。

游戏结果、时间推进等确定性逻辑应由规则模块处理；Agent 负责理解自然语言、组织体验和给出人格化反馈。

## 接入智能硬件

硬件适配器负责屏蔽品牌、协议和连接方式差异，对上提供统一语义接口：

```text
discover             发现设备
connect              建立连接
get_capabilities     返回设备能力
execute_action       执行语义动作
get_state            读取设备状态
stop                 安全停止
disconnect           断开连接
```

动作应描述意图，例如“表达开心”“看向用户”“显示提醒”“低速前进”，而不是把电机、舵机或厂商指令暴露给 Agent。适配器负责能力映射、范围限制、超时、安全停止和结果回报。

新眼镜、桌宠机器人或智能设备只需提供对应适配器，即可复用既有 Agent、记忆、工具和体验模块。

## 扩展 App 与眼镜界面

模块可以通过 `ui_slots` 声明界面入口，而无需改写应用导航核心。常见插槽包括：

- 首页功能卡片或快捷按钮；
- 状态页、详情页和设置页；
- 眼镜轻量提示卡片；
- 通知操作与语音入口；
- 设备状态和权限配置。

界面只负责呈现和输入，业务事实由相应模块或数据服务维护，避免多个终端产生互相冲突的状态。

## Mock 与测试

模块提交前应提供无需真实硬件或商业凭据即可运行的 Mock，并覆盖：

- 清单和依赖可被正确解析；
- 输入、输出和错误结构符合协议；
- 权限拒绝、超时、取消和重复调用；
- 设备断连、能力缺失与安全停止；
- Agent 能根据执行结果继续、重试或结束任务。

硬件适配器还应提供模拟设备状态，使体验模块可以与具体设备采购和接入并行开发。

## 版本、许可证与发布

- 模块采用语义化版本，并声明兼容的框架与协议版本。
- 第三方代码、模型、素材和服务必须标明来源与许可证。
- 模块不得包含密钥、账号、个人数据或无权再分发的 SDK。
- 破坏性接口变更应提升主版本并提供迁移说明。
- 商业模块也应遵守相同的能力、权限和安全边界。

## 参与生态

贡献内容可分为官方示例、社区模块、商业模块和认证硬件适配器。提交前请阅读仓库根目录的 `CONTRIBUTING.md`、`SECURITY.md` 与许可证说明，并附带最小示例、测试和清晰的权限声明。
