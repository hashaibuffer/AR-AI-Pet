# 跨端接口协议说明

`packages/protocol/` 是跨端协议的唯一事实来源。本文件只解释接口范围、责任和冻结节奏，不重复维护消息字段。

## 状态权威

- 单局游戏状态以 Beam Pro/XR 客户端为权威。Agent、宠物和设备只能读取事件并反馈，不能改写规则、计分或结算结果。
- 宠物长期记忆、虚拟生活和持久化状态以 Agent 服务为权威。客户端和设备重连后从 Agent 服务恢复这些状态。
- StackChan 与 NanoDrive 的实时设备状态以各自设备侧为权威。服务与客户端不得用期望状态覆盖设备实际状态。

当前 NanoDrive 的 BLE 路径为单向控制：StackChan 可确认 FFE1 写入请求被接受，但不能据此生成“设备已执行”的状态。实体运动结论只记录在实测验收中；状态回传接入前，服务端不持久化即时轮速或位置。

状态发生冲突时，以对应权威端的快照为准。跨端显示和缓存不成为新的事实来源。

## 协议文件与 Mock

- 正式定义：`packages/protocol/schemas/`。
- 可解析示例：`packages/protocol/examples/`。
- 开发 Mock：`packages/protocol/mocks/`。

以上目录在首次提交实际协议时建立，不预先创建空定义。Mock 和示例必须引用同一版正式定义，不得增加正式协议中不存在的字段或行为。

## 最小通信规则

- 重连：使用方先获取对应权威端的完整快照，再继续处理新事件；不能根据本地缺失事件自行推断最终状态。
- 重复事件：同一 `messageId` 只处理一次。计分、存档和运动指令不得因重发重复执行。
- 版本：发送方必须携带协议版本。接收方拒绝不支持的主版本并记录可定位问题；兼容范围在 Day 1 由实际使用方确认。
- Mock：真实模块未完成时仍使用正式协议、示例和固定 Mock 开发。真机接入不得另建一套临时字段。

## 变更要求

接口变更必须在同一个 PR 中同步更新：

- `packages/protocol/` 中的协议定义。
- 对应示例与 Mock。
- 所有直接使用方。
- 本文件中的状态或冻结阶段说明。

冻结后的跨模块修改至少由一名使用方确认。
