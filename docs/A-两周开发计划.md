## 3. GitHub 同步策略（贯穿全程）

> 详细命令见 [`A-详细操作步骤指南.md`](A-详细操作步骤指南.md) 第 0 章。这里只列原则。

- **分支模型：** 每个任务一个 `feat/a-<任务名>` 短期分支，不建个人长分支，不直接推 `main`。
- **每日节奏：** 上午开工前 `git pull`；每个子任务完成即 commit；下班前 push 当日分支并提 PR 或合并。
- **PR 规则：** 代码 + 协议 + Mock + 文档同 PR；跨模块改动至少一名使用方 review。
- **CI：** 合并前必须过仓库已有 CI（当前是 `deck-site.yml`）。
- **标签：** Day 4、Day 8、Day 10 由 B 打可回退 tag，A 配合提供客户端产物。
- **LFS：** 模型、音频、视频走 Git LFS，首次参与前执行 `git lfs install`。

### Day 3 · 游戏框架与快艇骰子核心

**目标：** 通用游戏框架落地；快艇骰子核心逻辑（投掷/保留/计分）可单机跑通。

**上午**

1. `git pull`，与 C 再次确认快艇骰子规则已冻结。
2. 建立游戏框架：
   - `GameManager`：局生命周期（开始/进行/结束）。
   - `GameState`：当前局快照（骰子值、保留标记、回合、计分表）。

**下午**

   - 5 颗骰子投掷，随机 1–6。
   - 保留选择（点击骰子切换保留）。
   - 一回合最多 3 次投掷。
   - 13 个计分组合（上区 1–6 + 下区三/四/葫芦/小顺/大顺/快艇/全计）。
   - 计分表 UI（临时文本即可）。
5. 本地跑通一局：投掷 → 保留 → 计分 → 结算 → 显示赢家（用户 vs 宠物 Mock）。
