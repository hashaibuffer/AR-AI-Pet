# 第一部分：路演概述

### 1. 一句话定位

**《桌屿 Deskle》是一款「AR 眼镜 + 实体桌面机器人」的桌面家园产品。**

戴上 眼镜，你的书桌变成一座小岛：一侧是四季轮转的农田，一侧是亮着霓虹的小酒馆，中间有一汪池塘。而桌上那台真实存在的小机器人，会在这座岛上跑来跑去——帮你浇水、替你收割、和你隔桌掷骰子。

### 2. 产品形态与硬件构成

| 层        | 构成                     | 承担什么                                |
| -------- | ---------------------- | ----------------------------------- |
| **实体层**  | 桌面机器人（约 12~15cm）+ 充电基站 | 真实的物理存在感、基础动作、陪伴、语音交互、桌面移动          |
| **AR 层** | Xray AR 眼镜             | 渲染整座家园（农田/酒吧/池塘/建筑/作物/骰子）、机器人的表情与特效 |
| **算力层**  | 眼镜主机端（分体式）             | 空间定位、渲染、游戏逻辑、机器人指令下发                |
| **连接层**  | BLE / Wi-Fi Direct     | 眼镜端 ↔ 机器人双向通信（位姿上报 + 动作指令）          |

**「实体为主 + AR 增强」的分工原则：**

| 由实体机器人完成     | 由 AR 叠加完成                         |
| ------------ | --------------------------------- |
| 桌面移动、转向、靠近   | 面部表情（全息叠加在机器人「脸屏」外圈）              |
| 头部俯仰/偏航、底盘移动 | 情绪符号（`!?` / `zzz` / 爱心）漂浮         |
| 语音播报、音效发声    | 夸张动作补足（跳跃、转圈、变形，由 AR 分身承载）        |
| 浇水/播种等真实物体交互 | 光效、粒子、水流、作物生长动画（由 AR 全息特效表达，无机械臂） |
| LED 灯带情绪色    | 机器人身上的装饰/皮肤/等级标记                  |

> **设计原则**：**凡是实体能做的，优先让实体做**——物理动作带来的临场感是 AR 无法替代的；AR 只补足实体做不到的部分（表情细腻度、夸张幅度、光效）。

### 3. 目标用户

| 维度       | 描述                                    |
| -------- | ------------------------------------- |
| **核心人群** | 25~40 岁，有固定书桌/工位，追求桌面仪式感的科技爱好者与轻度玩家   |
| **次要人群** | 桌面机器人/智能硬件早期尝鲜者；AR 眼镜已购用户寻找杀手级内容      |
| **场景人群** | 居家办公者、需要「陪伴感」的独居用户、亲子家庭（家长与孩子共用一台机器人） |
| **反向排除** | 无固定桌面的重度移动用户；追求硬核长时长游戏的核心玩家           |

**典型用户画像：**

> 阿哲，31 岁，程序员，居家办公。桌上放着一台《桌屿》机器人。他不玩眼镜的时候，机器人就是个会转头看他、偶尔伸个懒腰的桌面摆件。工作累了戴上眼镜十分钟——收一茬胡萝卜，去酒馆跟机器人掷两把骰子，然后摘下眼镜继续干活。

### 4. 核心卖点与差异化

| 卖点           | 说明                                             |
| ------------ | ---------------------------------------------- |
| **虚实共生**     | 机器人是真的在桌上跑，作物是虚拟的长在桌上——摘下眼镜机器人还在，戴上眼镜世界就来了     |
| **一个角色贯穿全局** | 同一台机器人，在农田帮你浇水，在酒馆当你对手，在池塘陪你钓鱼；它的等级/外观/性格跨玩法一致 |
| **桌面即世界**    | 不占额外空间，你的书桌就是游戏地图；家园与真实桌面同尺度共存                 |
| **摘下眼镜也成立**  | 无眼镜时机器人进入「陪伴模式」（待机动画、报时、提醒），产品价值不完全依赖眼镜        |
| **统一经济闭环**   | 三个玩法共用一个金币钱包，赚哪儿花哪儿，跨玩法互相反哺                    |
| **零门槛碎片时间**  | 单次 5~10 分钟即可完成一个有意义的循环                         |

### 5. 竞品与参考

| 类型      | 参考对象                        | 借鉴点            | 我们的差异                    |
| ------- | --------------------------- | -------------- | ------------------------ |
| 桌面机器人   | LOONA / EMO / Vector        | 陪伴感、表情设计、桌面移动  | 它们没有 AR 世界，只是宠物；我们有完整玩法层 |
| AR 桌面游戏 | Tilt Five / Meta Quest 桌面应用 | 桌面锚定、同尺度呈现     | 它们纯虚拟，无实体角色              |
| 经营循环    | 星露谷物语（季节）/ 动物森友会（家园）        | 四季机制、家园建设的长线动力 | 我们是桌面尺度 + 碎片时长 + 虚实结合    |
| 骰子玩法    | Yahtzee（快艇骰子）               | 规则基底           | 实体机器人作为对手 + AR 全息呈现      |

### 6. 商业模式

**demo 阶段不做变现。** 商业模式待玩法验证后确定。
### 7. 核心循环

```
     [摘下眼镜] 机器人陪伴模式（待机/报时/提醒）
              ↓ 戴上眼镜
     ┌────────────────────────────────┐
     │      桌屿家园（俯视全景）         │
     └──┬──────────┬──────────┬───────┘
        ↓          ↓          ↓
     [农田]      [酒馆]     [池塘]
    《一寸春》  《六面星河》  钓鱼
        │          │          │
        └──────────┴──────────┘
                   ↓
            统一金币钱包
                   ↓
        买种子 / 买皮肤 / 升级机器人 / 建设家园
                   ↓
              回到家园全景
```

# 第二部分：详细设计

## 一、家园结构

### 1.1 空间定义

家园是**锚定在玩家真实桌面上的一块虚拟区域**，与真实桌面同尺度共存。

| 项目     | 规格               | 说明                         |
| ------ | ---------------- | -------------------------- |
| 最小面积需求 | 30cm × 30cm 平整区域 | 低于此尺寸引导玩家更换桌面或清理空间         |
| 推荐桌面尺寸 | 100cm × 60cm     | 完整布局，各功能区互不拥挤              |
| 家园虚拟尺度 | 1 单位 = 1cm 真实距离  | 严格同尺度，无缩放，保证机器人能真实走到 AR 位置 |
| 家园朝向   | 以玩家坐姿正前方为「北」     | 首次锚定时由玩家确认方向               |
| 高度基准   | 桌面平面 = Y=0       | 所有建筑与机器人立于此平面              |

### 1.2 家园布局（默认）

```
        ┌──────────── 真实桌面（俯视） ────────────┐
        │                                          │
        │   [🏠 机器人屋]              [🍺 酒馆]     │   ← 后排：建筑
        │    (充电基站)              《六面星河》    │
        │                                          │
        │   ┌──────────────┐         ╭────────╮   │
        │   │   🌱 农田      │         │ 🎣 池塘 │   │   ← 中排：玩法区
        │   │  《一寸春》     │         ╰────────╯   │
        │   │   (可扩展)     │                      │
        │   └──────────────┘                      │
        │                                          │
        │        ← 机器人自由活动区 →               │   ← 前排：留给机器人
        │                                          │
        └────────────────────────────────────────┘
                        ↑ 玩家坐这侧
```

**布局规则：**

| 规则       | 说明                                      |
| -------- | --------------------------------------- |
| 建筑靠后     | 高的建筑（机器人屋/酒馆）放远端，不遮挡近端操作                |
| 玩法区居中    | 农田/池塘在视线舒适区（距玩家 25~45cm）                |
| 前排留空     | 靠近玩家一侧留 10cm 空白，作为机器人「上桌口」与玩家手部操作区      |
| 可自定义     | 家园布局模式下，玩家可拖拽建筑重新摆放（Lv2 解锁）             |
| **实体避让** | AR 建筑自动避开桌面上被识别到的真实障碍物（水杯/键盘），不会「长在杯子上」 |

### 1.3 实体障碍融合

这是「AR 眼镜 + 真实桌面」的关键体验点：

| 情况       | 处理                                      |
| -------- | --------------------------------------- |
| 桌上有水杯/笔筒 | AR 识别为障碍柱，家园布局自动避让；机器人路径规划绕行            |
| 桌上有键盘/本子 | 识别为高地平面，AR 可在其上生成「高台」地形（如池塘边的岩石） `[提案]` |
| 障碍物中途出现  | 实时重规划机器人路径；若压到 AR 建筑，该建筑淡出并提示「有东西挡住了农田」 |
| 障碍物移走    | 建筑淡入恢复                                  |

> **体验价值**：玩家把咖啡杯放到桌上，机器人会绕着杯子走——这一刻虚拟与现实真正打通了。

## 二、功能区与解锁

### 2.1 功能区总表

| 功能区      | 形态                   | 初始状态              | 解锁条件       | 承载内容              |
| -------- | -------------------- | ----------------- | ---------- | ----------------- |
| **农田**   | AR 地块 + 实体机器人参与      | ✅ 初始开放            | —          | 《一寸春》全部玩法         |
| **机器人屋** | **实体充电基站** + AR 外观包裹 | ✅ 初始开放            | —          | 机器人充电/休息、委托板、养成升级 |
| **酒馆**   | AR 建筑，内部切全息风         | 🔒 锁定             | 农场 **Lv2** | 《六面星河》骰子对战        |
| **池塘**   | AR 水域                | 🔒 锁定             | 农场 **Lv5** | 钓鱼玩法（post-MVP）    |
| **装饰位**  | AR 摆件                | 🔒 锁定             | 农场 **Lv5** | 家园装饰、皮肤、自由布局      |
| **仓库**   | AR 小屋                | ✅ 初始开放（简化为 UI 面板） | —          | 种子/作物/材料库存        |

### 2.2 解锁节奏设计意图

```
第 1~14 回合（春季）：只有农田 + 机器人屋
    └─ 专注学会核心循环：耕→种→浇→收→卖
       机器人以「新手帮手」身份陪伴，教学任务由它发布

农场升到 Lv2
    └─ 同时解锁 酒馆 
       家园从「一块田」扩展为「一座岛」，给出明确的成长反馈时刻
```


### 2.3 解锁演出

| 阶段 | 表现 |
|---|---|
| 达成条件瞬间 | 机器人（实体）转身面向玩家，举起双手，头部 LED 闪烁彩光 |
| AR 演出 | 桌面出现光带扩散，酒馆/池塘/装饰位从桌面「升起」建造动画（~4s） |
| 语音 | 机器人语音播报：「农场升级啦！酒馆和池塘都开了，去看看吧！」 |
| 引导 | 新功能区上方出现 AR 引导箭头，首次点击后消失 |

## 三、导航与场景切换

### 3.1 三层视图结构

```
  L0  家园全景视图（默认）
       ├─ 俯视整张桌面，看到所有功能区
       ├─ 机器人在桌上自由活动
       └─ 指向（手部追踪）+ 捏合 选中建筑 → 进入 L1
                  ↓
  L1  玩法视图（农田 / 酒馆 / 池塘）
       ├─ 相机不移动（眼镜是第一人称，物理上就在原位）
       ├─ 非当前玩法区淡化/半透明（focus 效果）
       ├─ 当前玩法区细节层级提升（LOD 拉满、UI 面板浮现）
       └─ 手势「返回」或语音「回家园」→ 回 L0
                  ↓
  L2  子界面（委托板 / 商店 / 图鉴 / 设置）
       └─ 悬浮 2D 面板，位于玩家正前方 40cm，跟随头部缓动
```

> **关键差异（相对手机 AR）**：眼镜是第一人称，**没有虚拟相机移动**。所谓「进入酒馆」不是镜头飞进去，而是**酒馆区域的内容展开、其余区域淡化**。玩家的头本身就是相机，转头就能看别处。

### 3.2 视图切换规则

| 操作 | 方式 | 反馈 |
|---|---|---|
| 选中功能区 | 指向 + 捏合 / 语音「打开农田」 | 目标区高亮描边，0.3s 后展开 |
| 返回家园 | 手势「张开手掌下压」/ 语音「回家园」/ 指向返回按钮 | 其余区域淡入恢复 |
| 打开子面板 | 点击对应 UI 入口 | 面板从入口位置弹出并缓动到正前方 |
| 关闭子面板 | 手势「捏合并向下甩」/ 语音「关闭」 | 面板收回原位 |
| 快速切换 | 语音直呼「去酒馆」/「去农田」 | 跳过 L0，直接切到目标 L1 |

### 3.3 机器人的场景跟随

机器人是实体，**不存在「加载到某个场景」**，它始终在桌上。视图切换时它的行为：

| 视图 | 机器人行为 |
|---|---|
| L0 家园全景 | 在桌面自由漫游（巡视农田、绕池塘走、靠近玩家打招呼） |
| L1 农田 | 移动到农田区边缘待命，接受浇水/收获指令 |
| L1 酒馆 | 移动到酒馆桌位（AR 酒馆内的对面座位），进入对战姿态 |
| L1 池塘 | 移动到池塘边，做垂钓陪伴动作 |
| L2 子面板 | 保持当前位置，做闲置动画；若面板是「委托板」，它会靠近并指点 |

> **移动耗时**：机器人从桌面一端走到另一端约 2~4 秒。视图切换不等待机器人到位（不阻塞），它一边走玩家一边可以操作。

## 四、统一金币钱包

### 4.1 设计目标

三个玩法（农田/酒馆/池塘）共用**一个金币池**，实现跨玩法互相反哺，让「玩哪个都不算浪费」。

### 4.2 收支总表

| 玩法 | 收入来源 | 支出去向 |
|---|---|---|
| **农田《一寸春》** | 卖作物、首次收获奖励、连续收获奖励、委托奖励 | 买种子、扩建土地、买装饰 |
| **酒馆《六面星河》** | 对局胜负奖励、段位奖励 | 买骰子皮肤/桌面主题/特效 |
| **池塘（钓鱼）** | 卖鱼 | 买鱼饵/钓具 |
| **家园层** | — | 家园装饰、机器人外观皮肤 |

### 4.3 跨玩法流动示例

```
在酒馆赢了 3 局（+45 金）→ 回农田买了 3 颗草莓种子（-150 金，还差）
在农田卖了南瓜（+200 金）→ 回酒馆买了一套「星河」骰子皮肤（-180 金）
```

### 4.4 钱包规则

| 规则 | 说明 |
|---|---|
| 单一余额 | 全局唯一 `wallet.coins` 字段，无子账户 |
| 起始金币 | **50 金**（详见《一寸春》经济章） |
| 上限 | 无硬上限；UI 超过 99,999 后简写为 `10.2万` |
| 流水记录 | 记录最近 100 条收支，可在家园「账本」面板查看 `[提案]` |
| 负数保护 | 任何消费前校验余额，不足时按钮置灰并提示 |
| 存档一致性 | 钱包写入采用「先扣款后发货、失败回滚」的事务式处理，防止断电丢币 |

### 4.5 平衡关注点

| 风险 | 说明 | 对策 |
|---|---|---|
| 酒馆刷金 | 骰子单局 7~10 分钟收益若高于农田同时长，玩家会放弃种田 | 骰子单局收益（胜 15 金）刻意低于农田同时长收益，定位为「消遣小钱」 |
| 农田通胀 | 后期南瓜/向日葵利润高，骰子皮肤瞬间买光 | 骰子皮肤定价随解锁递增（80/180/400/800 金），保持长期目标 |
| 跨玩法失衡 | 玩家只玩一边 | 每日「跨玩法任务」`[提案]`：今日在两个玩法各活动一次，额外 +30 金 |

## 五、实体桌面机器人（硬件）

> 机器人是整个产品的**灵魂角色**，也是最大的差异化。本章定义硬件规格；它在各玩法中的行为详见对应 GDD。

### 5.1 角色设定

| 项目      | 设定                            |
| ------- | ----------------------------- |
| **名字**  | 由玩家开机时命名                      |
| **性格**  | 爱卖萌、勤快、有点小脾气；会因为被夸奖开心，被冷落会闹别扭 |
| **身份**  | 玩家的家园伙伴，既是农场帮工，也是酒馆对手，也是钓鱼搭子  |
| **一致性** | 全局唯一角色，跨玩法共享等级/外观/情绪状态        |


### 5.2 陪伴模式（无眼镜时）

产品价值不能 100% 依赖眼镜。玩家不戴眼镜时，机器人进入**陪伴模式**：

| 行为        | 触发             | 表现                     |
| --------- | -------------- | ---------------------- |
| 待机呼吸      | 常态             | 缓慢左右转头，眼睛偶尔眨动，灯带呼吸     |
| 打招呼       | 检测到玩家靠近/说话     | 转向玩家，眨眼，播放问候音          |
| 报时        | 整点 `[提案]`      | 播报时间，短动作               |
| 番茄钟       | 语音「开始专注」`[提案]` | 计时期间安静待机，结束后提醒         |
| 农场提醒      | 有作物成熟/委托到期     | 转向玩家，灯带闪黄，语音「田里的胡萝卜熟啦」 |
| 回桩充电      | 电量 <20%        | 自动返回机器人屋充电             |
| 情绪积累      | 长时间无互动         | 灯带转蓝，动作变少，戴上眼镜后会「闹别扭」  |
| 自己在农场世界种植 | 随机             | led显示当前状态              |

> **战略意义**：陪伴模式让机器人在 90% 的时间里（不戴眼镜时）依然有存在价值，这是硬件复购与口碑的基础。

### 5.3 机器人与真实骰子的交互（酒馆场景）

《六面星河》中骰子的形态已由骰子 GDD 定稿（见该文档第六章、第十四章）：

| 决策项 | 最终方案 | 说明 |
|---|---|---|
| **骰子形态** | **全息骰子（原方案 A）** | 骰子完全虚拟（发光骰体），由**玩家手势/语音**发起投掷，全息骰子从桌面中央光阵以光粒凝聚飞出、弹跳静止；无实体骰子，规避丢失与识别难题 |
| **机器人形态** | **无臂实体装置 + AR 虚拟分身** | 真实物理机身坐桌对面（含 LCD 面屏基础表情 + 头部/滚轮底盘/灯带微动，无机械臂），眼镜叠加全息孪生分身做夸张表情与超越物理极限的表演（跳跃/旋转/变形） |
| **为何不选实体骰子** | — | 实体骰子在真实桌面抛掷存在掉落/丢失/识别可靠性风险，且与强制 AR 无降级原则冲突；全息方案以 AR 表现保证可控与沉浸 |

## 六、实体 × AR 融合层

> 本章是本项目**最核心的技术与体验设计**，决定「实体机器人」与「AR 世界」是否真的融为一体。

### 6.1 融合的三个层次

| 层次       | 要求                             | 失败后果                |
| -------- | ------------------------------ | ------------------- |
| **空间对齐** | AR 世界坐标系与机器人物理坐标系精确对齐（误差 <1cm） | 机器人「浇水」浇到田块外面，穿帮    |
| **时序同步** | 实体动作与 AR 特效同时发生（误差 <100ms）     | 机器人动作已完成，水流特效才出来    |
| **语义一致** | 实体状态与 AR 表现描述同一件事              | 机器人在充电，AR 却显示它在田里干活 |

### 6.2 空间对齐方案

```
     ┌─────────────────────────────────────────┐
     │  AR 眼镜端（世界坐标系 W）                │
     │                                          │
     │   1. SLAM 建立桌面平面 → 定义家园原点 O   │
     │   2. 视觉识别机器人顶部基准标记            │
     │      → 得到机器人在 W 中的位姿 T_robot     │
     │   3. 融合机器人上报的里程计数据（BLE）      │
     │      → 卡尔曼滤波，得到高频稳定位姿         │
     │   4. 下发目标点（以 O 为原点的坐标）        │
     └──────────────┬──────────────────────────┘
                    │ BLE
     ┌──────────────▼──────────────────────────┐
     │  机器人端（自身坐标系 R）                  │
     │   5. 接收目标点 → 路径规划 → 执行移动      │
     │   6. 上报里程计 + IMU（20Hz）              │
     └─────────────────────────────────────────┘
```

| 环节      | 技术选型 `[提案]`                | 精度目标             |
| ------- | -------------------------- | ---------------- |
| 桌面平面检测  | 眼镜 SLAM 平面拟合               | 平面法向误差 <2°       |
| 机器人位姿识别 | 顶部 AprilTag（边长 2cm）视觉识别    | 位置误差 <5mm，角度 <3° |
| 高频位姿维持  | 里程计 + IMU 融合，视觉每 0.5s 校正一次 | 两次校正间漂移 <3mm     |
| 目标点下发   | 家园坐标系 (x, z, yaw)          | —                |
| 端到端指令延迟 | BLE 直连                     | <80ms            |

**遮挡与丢失处理：**

| 情况        | 处理                                   |
| --------- | ------------------------------------ |
| 标记被玩家手挡住  | 依赖里程计推算，最长维持 3s；超时后机器人减速待命           |
| 机器人跑出眼镜视野 | 语音提示「小屿跑到你看不见的地方了，转头看看」；机器人自动返回视野中心区 |
| 位姿漂移超阈值   | 触发重定位：机器人原地转一圈，眼镜重新识别标记              |
| 眼镜追踪丢失    | 家园 AR 内容暂停渲染，机器人立即停止移动（安全优先）         |

### 6.3 时序同步方案

以「机器人给一块田浇水」为例：

```
 t=0ms     眼镜端：玩家发出「浇水」指令
 t=+30ms   眼镜端：路径规划，下发「移动到田块 A3」
 t=+30ms   眼镜端：AR 播放「机器人接到指令」提示（头顶感叹号）
 t=~2000ms 机器人：到达 A3 边缘，上报「到位」
 t=+2050ms 眼镜端：下发「执行浇水动作」
 t=+2100ms 机器人：机身前倾下压（头部 + 底盘微动，实体动作，耗时 800ms）
 t=+2150ms 眼镜端：AR 水流粒子从机器人前方喷出（延迟 50ms 起，与实体动作重叠）
 t=+2900ms 机器人：动作完成，上报
 t=+2900ms 眼镜端：AR 水流停止，田块变为「已浇水」状态，作物生长值 +1
```

| 同步原则 | 说明 |
|---|---|
| **AR 特效跟随实体动作，而非反之** | 实体有机械延迟且不可精确控制，AR 是软件，让 AR 去等实体 |
| **动作前预告** | 实体动作有延迟，先用 AR 提示（头顶符号）填补等待感 |
| **动作失败兜底** | 机器人执行失败（被挡住/卡住）时，AR 播放「机器人挠头」+ 该操作改为玩家手动完成 |
| **可跳过** | 玩家不想等机器人时，可手势直接自己浇水，机器人转为旁观 |

### 6.4 表情：实体屏 + AR 叠加

| 层 | 内容 | 说明 |
|---|---|---|
| **实体面屏** | 基础眼睛表情（~12 种）：睁眼/眨眼/开心/失落/震惊/思考/生气/困倦… | 摘下眼镜也能看到，是机器人「本体人格」 |
| **AR 叠加** | 情绪符号（`!?` / `zzz` / `♪` / 汗滴）、腮红、夸张变形、光晕 | 戴上眼镜后表情张力大幅提升 |

**分工示例——机器人在酒馆输了一局：**

| 层 | 表现 |
|---|---|
| 实体 | 面屏切换为 `T_T`，头部低下 15°，底盘后缩，灯带转蓝，播放低沉音效 |
| AR | 头顶飘落灰色小雨云，肩膀处冒出「唉…」文字气泡，身体轮廓短暂灰化 |

> 摘下眼镜，你看到一个低着头蓝灯的小机器人；戴上眼镜，它头上还下着雨。**实体保证下限，AR 拉高上限。**

### 6.5 降级策略

| 故障         | 降级方案                            |
| ---------- | ------------------------------- |
| 机器人未开机/离线  | AR 生成**虚拟机器人替身**，玩法完整可用         |
| 机器人电量耗尽    | 自动回桩，AR 替身也休息                   |
| 机器人卡住/无法到达 | 该次协作改为玩家手动，AR 播放机器人道歉动画         |
| 眼镜未佩戴      | 机器人陪伴模式（5.4）                    |
| **两者都不可用** | 无产品体验（这是硬件产品的固有约束，通过双降级已最大化可用性） |

## 七、AR 基础层（三份文档共用底座）

> 本章定义的能力被《一寸春》《六面星河》共同调用，各自 GDD 不再重复描述。

### 7.1 桌面锚定流程

```
启动 → 环境扫描引导 → 桌面平面检测 → 玩家确认区域 → 确认朝向 → 锚点建立 → 加载家园
```

| 步骤     | 表现                     | 失败处理                           |
| ------ | ---------------------- | ------------------------------ |
| 环境扫描引导 | AR 提示「请缓慢环视你的桌面」，扫描进度环 | 光线不足 → 提示开灯                    |
| 平面检测   | 检测到的桌面高亮为蓝色网格          | 未检出 → 提示「桌面反光/太空旷，试试放一张纸或换个桌子」 |
| 区域确认   | 玩家用手势拖拽调整家园边框          | 区域 <30×30cm → 提示空间不足           |
| 朝向确认   | 显示「北」方向箭头，玩家可旋转        | —                              |
| 锚点建立   | 播放家园「生成」动画（~3s）        | —                              |
| 记忆桌面   | 保存该桌面特征，下次自动识别恢复       | 特征不匹配 → 走完整流程                  |

### 7.2 三层 AR 容错（强制 AR 无降级前提下）

| 层级 | 场景 | 处理 |
|---|---|---|
| **第 1 层：首进强引导** | 首次检测失败 | 分步引导（调光线/清理桌面/更换位置），未成功不进入家园 |
| **第 2 层：锚定后容错** | 短暂丢追踪（<3s） | 使用最后有效锚点继续渲染，画面轻微冻结但不中断；机器人减速待命 |
| **第 3 层：重锚机制** | 长时间丢追踪（>3s） | 弹出「重新对齐桌面」提示，玩家指向桌面 2s 或说「重新对齐」即可快速重锚，游戏状态完整保留 |

### 7.3 环境光照与阴影

| 项目        | 方案                                   |
| --------- | ------------------------------------ |
| 环境光估计     | 眼镜 API 提供环境光强度与主光方向，实时应用于 AR 物体      |
| 阴影        | 简化接触阴影（Shadow Plane 圆形软阴影投在桌面），非实时光追 |
| 色温匹配      | AR 物体色温跟随环境（暖光房间 → 家园偏暖），增强融合感       |
| **机器人阴影** | 实体机器人有真实阴影；AR 不额外为其生成阴影，避免双影穿帮       |

### 7.4 遮挡处理

| 类型 | 方案 |
|---|---|
| 玩家手部遮挡 | 眼镜手部追踪生成手部遮挡蒙版，手在 AR 物体前时正确遮挡 |
| **实体机器人遮挡 AR** | 关键需求：机器人走到 AR 建筑前时必须挡住它。方案：用机器人位姿驱动一个不可见的碰撞代理体（proxy mesh）写入深度缓冲 |
| 真实物体遮挡 | 依赖眼镜深度感知能力；无深度传感器时退化为「AR 恒在前」并接受穿帮 `[待确认]` |

### 7.5 舒适度设计

| 项目 | 规格 |
|---|---|
| 内容距离 | 主要内容位于 30~60cm，避免过近引起辐辏冲突 |
| UI 面板距离 | 固定 40cm，头部缓动跟随（阻尼 0.15s） |
| 单次时长建议 | 15~20 分钟提示休息 `[提案]` |
| 帧率 | ≥ 60fps 稳定，掉帧时优先降低粒子密度而非分辨率 |
| 视场利用 | 家园全景不超出眼镜 FOV 中心 80% 区域，避免边缘裁切焦虑 |

## 八、交互输入体系

> **重要变更**：从手机 AR 迁移到 AR 眼镜后，「点击屏幕按钮」不再存在。全部交互改为**指向 + 捏合 + 语音**双通道（眼动凝视不在当前设计范围，以手部追踪当光标替代）。

### 8.1 双通道分工（指向 + 捏合 + 语音）

| 通道 | 适用操作 | 优势 | 劣势 |
|---|---|---|---|
| **指向（Point）** | 选中目标、瞄准（手部追踪当光标） | 快、自然、零学习成本 | 需捏合确认防误触；依赖手部追踪精度 |
| **手势（Hand）** | 确认、拖拽、精细操作 | 直观、有仪式感 | 长时间抬手疲劳、识别有误差 |
| **语音（Voice）** | 快捷指令、指挥机器人 | 无需抬手、可批量 | 公共场合不便、识别延迟 |

**核心组合：指向选中 + 捏合确认**（手部追踪当光标，指向即高亮），语音作为完整替代通道（满足 8.4 红线）。

### 8.2 手势词典（全局通用）

| 手势 | 动作 | 语义 |
|---|---|---|
| **捏合（Pinch）** | 拇指食指相触 | 确认 / 选中 |
| **捏合拖拽** | 捏住后移动 | 拖动物体（种子、装饰、面板） |
| **张开手掌下压** | 五指张开向下压 | 返回 / 关闭 |
| **手掌横扫** | 掌心朝下左右扫 | 翻页 / 切换 |
| **双手拉伸** | 两手捏合后拉开 | 缩放（仅家园布局模式） |
| **食指点触** | 指尖触碰 AR 物体 | 直接交互（近距离，如点田块） |
| **招手** | 手掌左右摆动 | 呼唤机器人过来 |

### 8.3 语音指令体系

| 类别 | 指令示例 | 响应方 |
|---|---|---|
| **导航** | 「去农田」「回家园」「打开酒馆」 | 系统 |
| **机器人（4 条基础）** | 「浇水」「收获」「播种」「接受委托」 | 机器人 |
| **机器人（呼唤）** | 「小屿过来」「小屿看这里」 | 机器人 |
| **系统** | 「关闭」「暂停」「保存」 | 系统 |

| 参数   | 规格 `[提案]`                  |
| ---- | -------------------------- |
| 唤醒方式 | 免唤醒词（家园内常听）+ 「小屿」作为机器人专属唤醒 |
| 拾音   | 机器人麦克风阵列为主，眼镜麦克风为辅         |
| 识别延迟 | <500ms（本地关键词识别，不走云端）       |
| 语言   | demo 仅中文普通话                |
| 静音模式 | 可全局关闭语音输入（公共场合）            |

### 8.4 无障碍与场景适配

| 场景 | 适配 |
|---|---|
| 不便出声（办公室） | 全部功能可通过指向+手势完成，语音非必需 |
| 不便抬手（吃饭时） | 核心操作可通过语音完成，手势非必需 |
| 单手操作 | 所有手势为单手手势，双手手势仅用于非必需的布局缩放 |

> **设计红线**：**手势与语音必须互为完整替代**，任何操作不得只有单一通道可达。

## 九、美术与风格桥接

### 9.1 三种风格的关系

| 区域 | 风格 | 关键词 |
|---|---|---|
| **家园全景** | 治愈系低多边形 | 温暖、柔和、明亮、圆润 |
| **农田《一寸春》** | 治愈系低多边形（同家园） | 田园、生机、四季色彩 |
| **酒馆《六面星河》** | 全息高科技 | 深蓝、霓虹、数据流、冷光 |
| **池塘** | 治愈系低多边形 + 水面反射 | 清澈、宁静 |

### 9.2 风格桥接手法

**问题**：治愈田园与全息科技是两种对立调性，直接并置会撕裂。

**解法：把酒馆做成「家园里的一间科技酒吧」，从外到内渐变。**

| 层次 | 表现 |
|---|---|
| 家园全景中的酒馆外观 | 低模小房子造型（与家园一致），但窗户透出**冷蓝色霓虹光**，屋顶有小型全息招牌 |
| 靠近/选中时 | 门口光带亮起，冷蓝光溢出到周围桌面一小圈 |
| 进入酒馆（L1） | 家园其余部分淡化压暗，酒馆区域展开为全息空间，色调完全转为深蓝 + 霓虹 |
| 返回家园 | 冷蓝收回屋内，暖色调恢复 |

> 这样玩家感受到的是「从暖洋洋的院子走进一间赛博酒吧」——反差成为特色而非割裂。

### 9.3 色彩规范

| 用途 | 色值 `[提案]` | 说明 |
|---|---|---|
| 家园主色（暖） | `#E8C48A` / `#C9A063` | 土地、木质建筑 |
| 农田绿 | `#7BAE4F` / `#3B6D11` | 作物、草地 |
| 池塘蓝 | `#6FB3C9` | 水面 |

## 十、音频体系

### 10.1 三个发声源

| 源 | 内容 | 特点 |
|---|---|---|
| **机器人扬声器（实体）** | 机器人语音、动作音效、情绪音 | 声音来自桌面真实位置，空间感真实 |
| **眼镜扬声器** | BGM、UI 音效、环境音、AR 特效音 | 空间音频，可定位到 AR 物体位置 |
| **协同** | 关键事件双源配合 | 如收获：机器人发出「叮」，眼镜播放作物弹出音 |

> **重要体验点**：机器人的声音**真的从桌上那个位置传来**，这是纯 AR 无法做到的。所有机器人相关音效优先由实体扬声器输出。

### 10.2 音频风格

| 区域 | BGM | 音效 |
|---|---|---|
| 家园全景 | 轻快治愈木吉他 + 钢片琴，循环 90s | 自然音（鸟鸣、微风）点缀 |
| 农田 | 同家园，稍活泼 | 卡通化音效（挖土「噗」、浇水「哗」、收获「叮咚」） |
| 酒馆 | 低速电子 Lo-fi | 电子音（数据流、光纹扫描） |
| 池塘 | 极简环境音 + 水声 | 抛竿、咬钩、收线音 |

### 10.3 音量与场景

| 项目 | 规格 |
|---|---|
| 机器人音量 | 3 档可调 + 静音；夜间模式自动降低 |
| BGM 默认 | 40%，可关 |
| 语音播报 | 可关闭（改为文字气泡） |
| 空间音频 | 眼镜端 AR 音效绑定 3D 位置 |

## 十四、MVP 分期路线

> **原则：农场 MVP 优先。** 先把「虚实融合」这件最难的事在最简单的玩法上跑通，再扩展内容。

### 14.1 分期规划

| 阶段 | 目标 | 内容 | 验证什么 |
|---|---|---|---|
| **M0 技术验证** | 虚实融合可行 | 桌面锚定 + 机器人位姿对齐 + 一次「机器人走过去浇水 + AR 水流」的完整闭环 | **空间对齐精度是否够、时序同步是否自然** |
| **M1 农场 MVP** | 核心循环成立 | 家园全景（仅农田+机器人屋）、耕种浇收卖、3 种作物、机器人基础协作、金币钱包、手势+语音输入 | 玩家是否愿意每天回来种田 |
| **M2 机器人深化** | 角色魅力成立 | 委托系统、双向互助、3 级养成、情绪系统、陪伴模式 | 机器人是不是「有人格的伙伴」而非工具 |
| **M3 季节与扩展** | 长线动力成立 | 4 季系统、6 种作物全开、装饰与布局、本地纪录 | 玩家能否玩过一整年（56 回合） |
| **M4 酒馆** | 第二玩法接入 | 《六面星河》骰子对战、酒馆解锁、跨玩法钱包流动 | 两个玩法是否互相促进 |
| **M5 池塘** | 内容补完 | 钓鱼玩法 | — |
| **M6 联网** | 社交扩展 | 账号、云存档、段位真榜、好友互访 `[远期]` | — |

### 14.2 各阶段交付判据

| 阶段 | 判据 |
|---|---|
| M0 | 机器人能在 <1cm 误差内走到指定 AR 田块并完成浇水，连续 20 次成功率 ≥ 90% |
| M1 | 内部测试者连续 5 天主动使用，单次时长 ≥ 5 分钟 |
| M2 | 测试者能说出机器人的「性格」，并对它有情感表述 |
| M3 | 测试者完成至少一个完整年度（56 回合） |
| M4 | 跨玩法金币流动实际发生（有人在酒馆赚钱买种子） |

### 14.3 风险最高的前置事项

| 事项 | 为什么关键 | 何时必须解决 |
|---|---|---|
| Xray 眼镜 SDK 能力摸底 | 决定手势/深度/音频方案是否成立 | **立项前** |
| 机器人位姿对齐精度 | 决定虚实融合是否成立，是整个产品的地基 | M0 |
| 桌面跌落保护 | 安全红线，一次事故毁掉产品 | M0 |
| 机器人续航与噪音 | 影响长期使用体验 | M1 |

## 十五、风险与对策

### 15.1 产品风险

| 风险 | 等级 | 说明 | 对策 |
|---|---|---|---|
| **双硬件门槛** | 🔴 高 | 要求玩家同时拥有 AR 眼镜 + 机器人，用户池极小 | ①先与眼镜厂商合作捆绑；②机器人支持「无眼镜陪伴模式」独立成立；③软件支持 AR 虚拟替身，降级可玩 |
| **桌面空间要求** | 🟡 中 | 需要 60×40cm 干净桌面，很多人桌上很乱 | 障碍避让设计让「乱桌面」也能玩；引导玩家清出小块区域即可起步 |
| **新鲜感衰退** | 🟡 中 | 虚实融合的惊艳感可能在 3 天后消退 | 靠季节系统 + 机器人养成 + 跨玩法提供长线；陪伴模式维持日常存在感 |
| **佩戴疲劳** | 🟡 中 | 眼镜长时间佩戴不适 | 单次循环设计为 5~10 分钟；20 分钟休息提示 |

### 15.2 技术风险

| 风险 | 等级 | 说明 | 对策 |
|---|---|---|---|
| **空间对齐精度不足** | 🔴 高 | 误差 >1cm 时机器人动作与 AR 明显错位，穿帮 | M0 阶段专项攻关；备选方案：放宽 AR 田块判定区域，用「大格子」容纳误差 |
| **实体动作延迟破坏节奏** | 🟡 中 | 机器人走 3 秒，玩家等得烦 | AR 预告填补等待；允许玩家跳过机器人自己操作；缩短家园布局距离 |
| **机器人遮挡 AR 失败** | 🟡 中 | 眼镜无深度感知时机器人会被 AR「穿透」 | 用代理体写深度缓冲；退化时接受轻微穿帮 |
| **语音识别可靠性** | 🟡 中 | 嘈杂环境误识别 | 本地关键词识别 + 短指令集 + 手势完整替代 |
| **BLE 稳定性** | 🟢 低 | 断连导致机器人失控 | 心跳检测，断连后机器人立即停止并回桩 |

### 15.3 硬件风险

| 风险 | 等级 | 对策 |
|---|---|---|
| 跌落损坏 | 🔴 高 | 三重 ToF + 软件安全边界 + 硬件急停优先级最高 |
| 电机噪音干扰 | 🟡 中 | 选用低噪减速电机；办公场景提供「静音模式」（降速） |
| 续航不足 | 🟡 中 | 自动回桩 + 边充边玩（在基站上仍可做上半身动作） |
| 量产成本 | 🟡 中 | 舵机数量控制在 7 个以内；面屏用低成本圆形 LCD |
