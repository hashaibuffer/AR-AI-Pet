# 实体小剧场与固定触发

首版只实现七个确定性场景：唤醒、晚安、玩乐、回家、提醒、安慰、跳舞。

## 调用规则

语音转成文字后，先由 `ExactSceneRouter` 做完整短句匹配。匹配成功时直接生成 `scene.play`，不调用大模型；其他自然语言继续走 Agent 推理。

唤醒由 StackChan 固件唤醒事件直接触发，不等待语音转写，也不能阻塞后续监听。

场景统一使用一个语义动作：

```text
scene.play(sceneId, durationMs, steps)
```

`steps` 只描述屏幕、灯光、头部和底座的语义动作，不出现 PWM、电机寄存器或串口参数。实体适配器负责执行和安全停止。

## 固定词

| 场景 | 固定词 |
|---|---|
| 唤醒 | 固件唤醒词事件 |
| 晚安 | 晚安、我要睡了、睡觉了 |
| 玩乐 | 陪我玩、玩一下、玩起来、玩乐 |
| 回家 | 我回来了、我到家了、回家了 |
| 提醒 | 日程到期、喝水提醒、休息提醒 |
| 安慰 | 安慰我、我有点难过、陪陪我 |
| 跳舞 | 跳舞、跳个舞、给我跳舞、跳舞吧 |

“我不想跳舞”一类带否定的语句不会触发固定场景，会交给 Agent 判断。

## 语音与动作

首版语音只安排在动作前或动作后，不要求语音、底座和舵机同时运行。场景开始时先播放 `voiceBefore`，再执行实体时间轴；`voiceAfter` 等动作完成事件接通后再启用。

唤醒不额外插入 TTS，只保留现有唤醒提示音，以保证用户可以立即继续说话。

## 安全约束

- 每个底座移动步骤都必须有明确的 `base_stop` 或时间轴终点。
- 新唤醒、新命令、遥控器和紧急停止可以打断当前场景。
- 遥控器优先级高于自动场景。
- 底座不可用时，场景降级为屏幕、灯光和头部动作。
- 场景结束必须恢复脑袋安全姿态、停止底座并恢复待机灯光。

## 实现边界

- Agent 服务：固定词路由、场景前后语音、事件记录和自然语言回退。
- Robot Bridge：只传递 `scene.play` 语义动作，不解释硬件参数。
- StackChan 实体适配器：voice-emoji 固件内置 `self.scene.play` / `self.scene.stop`，直接复用现有 Emoji、灯光、舵机和 NanoDrive BLE 动作；Robot Bridge 的语义映射仍保留给 Beam Pro/Agent 链路。
- Mock Robot：只验证场景接受、完成、取消和结果回传。

### 当前映射

| 语义步骤 | 固件动作 | 说明 |
|---|---|---|
| `display.emotion/icon` | `self.display.set_emotion` | `clock`→`thinking`，`music`→`laughing`，其余使用同名内置 Emoji |
| `led.effect` | `self.led.set_all` / `self.led.clear` | 渐变、呼吸和彩虹在 Bridge 侧展开 |
| `head.pose` | `self.robot.set_head_angles` | 只使用已验证的安全角度范围 |
| `base.move/stop` | `self.robot.base_move` / `self.robot.base_stop` | 运动结束自动补停，遥控和急停优先级不变 |

当前先把七个剧本搬入 voice-emoji 固件；COM7 启动日志已确认播放器任务和两个场景工具注册，动作时间轴、急停和遥控优先级仍需逐场执行观察。这不等于 Agent/Beam Pro 的真实 WebSocket/MCP 下发闭环已经通过。后续只需把同一 `scene_id` 从 Agent 或主会话触发到设备，再补回执记录。

本首版不加入猜拳、干杯、小动物和鲜花素材；这些属于后续图标资源包，不影响七个场景的接口。
