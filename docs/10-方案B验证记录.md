# 方案 B 验证记录（更新版）

更新时间：2026-08-10

本文件同时保留两类证据：

1. **历史 Scheme B**：Kimito 固件 + `stackchan-mcp` Gateway + Robot Bridge 的局域网能力验证；
2. **当前正式基线**：StackChan 实体 + Kimito 行为层 + AI.AGENT/Xiaozhi 语音会话 + 独立动作 MCP。

两者不能混写为同一条已经完成的端到端链路。历史 Scheme B 证明了本地 Gateway、相机、音频和 Robot Bridge 能力；当前正式基线证明了直接中文对话、触摸 PTT 和 Agent 到实体动作的设备子链路。

## 当前正式基线结论

当前采用的职责边界如下：

```text
AI.AGENT / Xiaozhi
  ├─ 主语音 WebSocket：ASR、会话、TTS、自动轮次
  └─ 独立动作 MCP WebSocket：调用 StackChan/Kimito 实体动作
           │
           ▼
StackChan 实体 + Kimito 行为层
  ├─ 麦克风、扬声器、触摸、屏幕和舵机
  ├─ 表情、头部反馈和陪伴表现
  └─ 本地安全边界，不接管云端会话
```

Beam Pro、Unity、NanoDrive 和其他 MCP 客户端仍是后续消费者，本记录不把它们宣称为完整端到端通过。

## 历史 Scheme B：Kimito 固件 + Gateway + Robot Bridge

历史 Scheme B 的架构如下，作为本地能力和替代部署路径保留：

```text
StackChan（Kimito 固件）
        │ WebSocket
        ▼
stackchan-mcp Gateway（局域网主机）
        │ MCP Streamable HTTP
        ▼
Robot Bridge（项目适配层）
        │ 项目 WebSocket
        ├── Agent / 数据服务
        └── Unity / Beam Pro
```

## 复现入口

### 当前正式基线

正式项目中的复现入口为：

```powershell
powershell -ExecutionPolicy Bypass -File .\firmware\stackchan-mcp\scripts\bootstrap.ps1
```

在 ESP-IDF 5.5.4 PowerShell 中构建：

```powershell
.\firmware\stackchan-mcp\scripts\build-accepted-baseline.ps1 `
  -GatewayUrl "ws://<本机动作网关地址>:8765/"
```

该脚本会校验固定 commit、套用电脑端配置、构建并生成一致性报告；不会调用 `flash`、`esptool` 或写入分区。

### 历史 Scheme B

历史评估源码位于 `D:\projects\stackchan-b-evaluation\`。项目侧 Robot Bridge 运行时只从本地环境变量读取地址和令牌：

```powershell
$env:ROBOT_GATEWAY_URL = 'http://<本机网关地址>:8767/mcp'
$env:ROBOT_GATEWAY_TOKEN = '<本地令牌>'
uv run python services/robot-bridge/scripts/bridge_smoke.py
```

## 当前边界与后续工作

- 本记录证明的是 StackChan/Xiaozhi 设备子链路和历史本地 Gateway/Robot Bridge 能力，不等同于完整 AR、Unity、Beam Pro、Agent、NanoDrive 端到端 Demo。
- 当前仓库存在两条容易混淆的动作入口：直接设备 `8080/ws` 与 Scheme B 的设备主动连接 `8765`、项目调用 `8767/mcp`。它们的连接方向不同，不能把一条路径的证据迁移到另一条路径。
- 现场实机联调前需补齐“设备 IP—电脑 IP—固件动作网关 URL—8765/8767 监听—网关设备会话”的成对记录；若设备仍指向旧电脑地址，先修正网关配置或刷入匹配配置，再验证 Agent 动作。
- 2026-08-13 的 COM7 启动探测确认 StackChan 已连接 BLE 底座并发现 `FFE0/FFE1`，但未连接到可用 Wi-Fi，因此本次没有建立动作网关会话；该结果只更新“断点定位”，不改变实体闭环状态。
- `beat_mode`、相机、动态头像和 `uart_diag` 属于历史 Scheme B 的能力证据，不是当前正式云端语音基线的必要组件。
- `gateway_config_set` 只用于首次部署、更换网关或故障恢复；普通交互不应频繁修改网络配置。
- `uart_diag` 只用于舵机总线和底座串口排查，不由 Agent 或 Unity 直接调用。
- Kimito 固件若继续分发或修改，按 AGPL-3.0 履行义务；`stackchan-mcp` Gateway 和当前固件改动按各自仓库许可证处理。
- 下一阶段应优先验证 Unity/Beam Pro → 项目服务 → 动作 MCP → StackChan 的真实闭环，再考虑把历史 Gateway 音频能力重新纳入正式产品路径。
