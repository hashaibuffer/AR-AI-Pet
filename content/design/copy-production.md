# 文案生产与交付

首版优先使用可审阅的固定文案，避免演示时因模型随机输出破坏节奏。

```text
场景/事件 → 选择 dialogueKey 与 innerOsKey → 按 personaId 取变体 → 插值事实字段 → 长度/事实检查 → 口播与 XR/App 分发
                                                        └─失败→固定 fallback
```

## 交付规则

- 每条文案有稳定 `key`，同一事件的口播和内心 OS 分开维护。
- 事实字段只来自事件或工具结果，例如 `{title}`；不把模型猜测插入模板。
- 同一 PR 同时更新编辑源、运行时 JSON 和示例/验收说明；运行时代码只读取 JSON。
- `purpose` 说明使用场景；三个人格至少各有一条变体，无法区分时使用 `default`。
- 新增台词先在 Mock Unity/机器人闭环验证，再进入演示脚本。

首版回退优先级：人格变体 → `default` → 行为规则中的 `speechPrompt`/`innerOsPrompt` → 空文本；不因文案缺失伪造动作成功。
