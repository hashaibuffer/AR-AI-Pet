# 桌屿系 · AR 交互与 UI 设计规范（v0.2）

> **范围声明**：本文档只规划**体验层**——UI 布局、交互方式、玩法节奏与反馈。
> 
> **不涉及**机器人硬件规格（尺寸/伺服/传感器/标记识别精度等），相关内容以「实体机器人作为交互对象存在」为前提，只在交互层面描述它「做什么、怎么被操作、给什么反馈」。
> 
> 配套 GDD：《桌屿 Deskle》家园系统 / 《一寸春》农场 / 《六面星河》骰子。
>
> **v0.2 修订**：去掉眼动凝视通道（可行性未定），交互改为**双通道（指向+捏合+语音）**；桌面机器人表达靠自有显示屏 + AR 眼镜分身 + 头部/滚轮底盘/灯带微动。

---

## 1. 体验设计原则

| 原则             | 含义                       | 设计落点                          |
| -------------- | ------------------------ | ----------------------------- |
| **双通道无屏**      | 不依赖手机/平板屏幕，全部操作由眼镜承载     | 指向(Point)+捏合(Pinch)+语音(Voice) |
| **通道互为替身**     | 任一操作必须有≥2种通道完成，绝不只有单一路径  | 手势（指向+捏合）与语音必须互相完整替代          |
| **实体为主·AR 增强** | 真实桌面机器人/物件是主载体，AR 只做叠加增强 | 全息 UI 锚定在实体之上，不漂浮孤立           |
| **零惩罚·治愈向**    | 不催促、不扣资源、不失败惩罚           | 休闲零碎时间娱乐                      |
| **锚定稳定优先**     | 全息UI必须能固定住点位             | 三层容错（首定强引导→锚定后宽容→可重锚）         |
| **反馈即时可感**     | 每个操作 100ms 内有可视/可听/可感反馈  | 光效+音效+机器人表现三重同步               |

## 2. 双通道交互模型

### 2.1 通道职责

| 通道 | 擅长 | 不适合 | 注意 |
|---|---|---|---|
| **指向 Point** | 选择/指向/悬停高亮（手部追踪当光标） | 精细数值输入 | 指向即高亮，需「捏合」确认防误触 |
| **捏合 Pinch** | 确认/拖拽/抛掷手势/旋转 | 长文本输入 | 食指+拇指轻捏即触发，松手取消 |
| **语音 Voice** | 指令/切换/询问/数值口述 | 安静环境受限 | 关键词唤醒 + 短指令，免唤醒词可选项 |

> 眼动凝视（Gaze）暂不使用：其硬件可行性未确认，且可被「指向+捏合」完全替代，故不在当前设计范围内。

### 2.2 全局映射表（所有游戏通用）

| 意图       | 指向+捏合           | 语音           | 备注        |
| -------- | --------------- | ------------ | --------- |
| 选中目标     | 手指标向目标→高亮       | 直说目标名        | 指向仅高亮，不触发 |
| 确认       | 指向+捏合           | "确认/就这个"     | 任一即可      |
| 取消/返回    | 指向返回区+捏合 / 手掌下压 | "返回/取消"      | —         |
| 主菜单      | 指向角标+捏合         | "菜单"         | —         |
| 帮助       | 指向"?"+捏合        | "怎么玩/帮助"     | 浮出引导光层    |
| 推进回合/下一步 | 指向"继续"+捏合       | "继续/过一天/下一局" | 玩法专用词见各章  |
| 暂停       | 指向暂停键+捏合        | "暂停"         | —         |

> **红线**：每个核心操作必须同时支持「手势（指向+捏合）」与「语音」两条路径，缺一不可。
> 选择机制：以**手部追踪当光标**指向目标，捏合确认；语音可直说目标名，二者等价。

## 3. 全息 UI 组件库

所有组件均为眼镜渲染的半透明全息层，锚定在实体桌面或机器人上。

| 组件                        | 形态                        | 用途                     | 视觉规范                  |
| ------------------------- | ------------------------- | ---------------------- | --------------------- |
| **光阵 (Holo-Field)**       | 桌面发光圆环/方格阵                | gameplay 主区域（种植格、骰子落点） | 直径随玩法缩放，柔光描边，不遮挡桌面纹理  |
| **计分板 (Scoreboard)**      | 悬浮半透明面板                   | 分数/金币/进度               | 右上信息带，字号≥可读，毛玻璃底      |
| **环形菜单 (Radial)**         | 以**指向点**为中心的弧选项           | 情境操作（种什么/掷骰/收杆）        | 3–6 项弧排，选中项放大高亮       |
| **提示气泡 (Hint)**           | 小光点+文字尾迹                  | 引导/校验反馈                | 出现即淡入，2s 自动隐，错误时变红抖一下 |
| **表情分身锚 (Avatar Anchor)** | 机器人头顶全息孪生（或者引入虚拟形象在ar显示层） | 夸张情绪表达                 | 锚定实体头部，头动带动分身，动作可超物理  |
| **进度环 (Progress Ring)**   | 目标物周圈弧形                   | 成熟/读条/冷却               | 顺时针填充，完成时迸发光粒         |
| **选择高亮 (Point Glow)**     | 指向目标描金边                   | 当前指向                   | 0.2s 渐显，离开渐隐          |

**通用视觉基调**
- 农场/家园：治愈低多边形 + 暖色柔光；骰子酒馆：冷调全息科技蓝。
- 动效节奏：入场 200ms 缓动，反馈 100ms 即时，退场 150ms 淡出。
- 深度：UI 默认浮在实体上方 2–5cm，避免与真实物件重叠导致眩晕。

## 4. 视野（FOV）布局规则

眼镜视野按「三带」划分，所有全息 UI 落入对应带，不越界：

```
┌─────────────────────────────────────┐
│  信息带 (Top)   计分板 / 金币 / 回合  │  ← 半透明，常驻
├─────────────────────────────────────┤
│                                     │
│   主交互区 (Center)                 │  ← 光阵/机器人/玩法主体
│   指向焦点 + 环形菜单在此展开        │
│                                     │
├─────────────────────────────────────┤
│  手势热区 (Bottom)  继续/菜单/暂停   │  ← 角标，低头可见
└─────────────────────────────────────┘
```

- **主交互区**占视野中心 60%，机器人坐对面、光阵铺桌面中央。
- **信息带**不随头动漂移（锁定世界坐标于桌面一角），避免眩晕。
- 单次同时出现的环形菜单项 ≤6，超出用「更多」二级弧。

## 5. 三游戏分步交互流程

> 每步标注可用通道：`[P]指向+捏合 [V]语音`（手势与语音等价）。

### 5.1 《一寸春》农场

| 步   | 玩家动作       | 通道                       | 系统反馈                                   |
| --- | ---------- | ------------------------ | -------------------------------------- |
| 1   | 进入农田区，指向空田 | [P]指向                    | 空田格亮起光阵，浮现「可种植」提示                      |
| 2   | 唤出作物环形菜单   | [P]捏合田格 / [V]"种什么"       | 弧列 7 作物（按当前等级解锁）                       |
| 3   | 选作物        | [P]指向+捏合 / [V]"玉米"       | 选中作物放大，显示利润/成熟回合                       |
| 4   | 确认播种       | [P]捏合 / [V]"种下"          | 光阵落入种子动画，进度环启动                         |
| 5   | 推进一天       | [P]指向"过一天"+捏合 / [V]"过一天" | 全局时间+1，成熟进度环填充                         |
| 6   | 收获成熟作物     | [P]指向成熟格+捏合              | 金币+，作物飞入仓库光效                           |
| 7   | 委托机器人代劳    | [V]"帮我除草" / [P]指向机器人+捏合  | 机器人以屏脸+头动+灯带+分身执行，完成 piggy-bank 结算 7/3 |
| 8   | 升级农田       | 累积收入达标自动提示               | 光阵扩格，解锁新作物                             |

**玩法节奏**：手动「过一天」驱动，无实时压迫；机器人协作是「省心选项」而非「必需」。

### 5.2 《六面星河》骰子

| 步 | 玩家/机器人动作 | 通道 | 系统反馈 |
|---|---|---|---|
| 1 | 进入酒馆，机器人坐定对面 | — | 桌面中央浮现骰子光阵，计分板亮起 |
| 2 | 掷骰（玩家发起；机器人偶尔抢先说「让我先开始吧~」，玩家可否决） | [P]抛掷手势 / [V]"掷" | 全息骰从光阵飞出弹跳静止；机器人以屏脸+头+灯带+分身做出期待反应 |
| 3 | 读点 | [P]指向骰面 / 自动 | 点数放大标注，计分板更新 |
| 4 | 选计分格（11 格任意填，**无上半/下半区顺序约束**） | [P]指向格+捏合 / [V]"填X格" | 高亮预览→确认填分动画 |
| 5 | 锁定/重掷（若有） | [P]捏合重掷键 / [V]"重掷" | 未锁定骰光粒重组 |
| 6 | 终局判定 | — | 机器人分身夸张庆祝/遗憾，光阵迸发结算 |
| 7 | 金币结算入统一钱包 | — | 计分板金币流入家园钱包光效 |

**玩法节奏**：11 局定胜负，单局 30–60s；全息骰飞出→静止≤1.5s，配合机器人反应（屏脸/头/灯带/分身）形成「它在跟我玩」的临场感。机器人**不掷骰**，掷骰动作始终由玩家发起。

### 5.3 《池塘》钓鱼（扩展·待 MVP 后）

| 步   | 玩家/桌宠动作     | 通道               | 系统反馈             |
| --- | ----------- | ---------------- | ---------------- |
| 1   | 指向池塘水面      | [P]指向            | 水面浮起鱼影光纹         |
| 2   | 抛竿          | [P]捏合上扬 / [V]"抛" | 全息浮标落水涟漪         |
| 3   | 咬钩感知        | —                | 浮标下沉+震动提示（眼镜/手表） |
| 4   | 收线 minigame | [P]节奏捏合 / [V]配合  | 张力环填充，鱼挣扎光效      |
| 5   | 入护          | [P]捏合 / [V]"收"   | 鱼入桶，图鉴点亮         |

## 6. 玩法设计要点（UX 视角）

### 6.1 回合循环节奏
- **农场**：玩家主动「过一天」→ 控制感强，零等待焦虑；机器人代劳让「挂机向」玩家也有正反馈。
- **骰子**：固定 11 局，节奏紧凑；AI 对手（实体机器人）每局对掷骰结果做**反应表演**（屏脸/头/灯带/分身），不机械抛骰，避免「跟电脑下棋」的冷感。偶尔主动请战「让我先开始吧」增添性格。
- **统一钱包**：农场赚的金币可直接去酒馆下注，跨区消费形成「一个桌屿、三种生活」的循环。

### 6.2 新手引导（无屏化）
- 首入用「光层引导」：虚线箭头 + 语音「指向这里，捏一下」，不弹长文。
- 8 步任务式引导（农场为例）：指向田→开菜单→选种→种下→过一天→收获→指向机器人→委托一次。
- 引导可随时「[V]跳过」，且不奖励跳过（避免被迫看）。

### 6.3 留存钩子（设计层）
- **装饰系统**：金币换桌面摆件，改变家园光阵外观（纯外观，不影响数值）。
- **本地记录**：最佳连胜、最大单日收入、图鉴收集度——以全息奖杯墙呈现。
- **机器人好感**：互动（指向+捏合摸头/对话）积累，解锁表情/语音彩蛋（设计层，不绑硬件）。

## 7. 反馈与音效原则

| 事件 | 视觉 | 音效 | 实体（机器人·无臂） | AR 分身 |
|---|---|---|---|---|
| 选中 | 指向高亮金边 | 轻"叮" | 轻微转头注视 | — |
| 确认 | 光粒迸发 | 清脆"咔" | 点头 + 灯带亮 | 小星星 |
| 错误/无效 | 红抖+提示气泡 | 低沉"噗" | 摇头 + 灯带闪红 | 问号 |
| 收获/得分 | 金币飞入+光柱 | 上扬铃音 | 底盘转圈 + 灯带金 | 撒花 |
| 机器人胜 | 结算迸发 | 胜利号角 | 点头 + 灯带金 + 底盘前倾 | 狂欢跳跃旋转 |
| 机器人败 | 结算暗淡 | 滑稽下行音 | 低头 + 灯带蓝 | 耷拉 |

> 机器人实体层**无手臂**，故鼓掌/举臂/捂脸等肢体动作改为由 AR 分身（虚拟）承载；实体层仅用屏脸、头部（点头/摇头/前倾/转头）、滚轮底盘（转圈/前倾/小幅移动）、灯带（变色）表达。
> **三源音**：眼镜近场（UI 反馈）+ 实体机器人（角色音）+ 环境底乐（治愈向），互不抢频。
> **静音通道**：语音指令环境嘈杂时，纯手势路径（指向+捏合）仍可 100% 完成全部操作。
