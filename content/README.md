# 内容交付

## 模块用途

本目录保存 C 主责的人格、规则、交互体验、数值、文案和正式资源。

## 主责人

C。A、B确认内容能否由各自模块实现和读取。

## 当前状态

交付格式已定义；具体规则和资源待 C 提交。

## 文件格式

- Markdown：规则、人格、交互流程和体验说明。
- CSV 或 JSON：游戏数值、文案、状态、情绪与动作映射，供程序读取。
- XLSX：允许作为 C 的编辑源文件，但不能作为程序唯一数据源。
- PNG、SVG、音频、模型：正式资源。

## 资源要求

每项资源必须有稳定的英文 `resourceId`。代码通过 `resourceId` 或清单引用资源，不能依赖可随意修改的中文文件名。

交付时注明用途、版本和是否可直接进入 Demo。尚未确认的内容标记为“待负责人确认”。

## 安装或运行方式

无独立运行命令。程序可读格式和导出方式待 C 与使用方确认。

## 配置入口

待 C 按具体交付建立内容清单。

## 依赖的协议

涉及跨端状态与事件时引用 [`packages/protocol/`](../packages/protocol/)。

## 验证方式

A、B验证程序可读取的 CSV 或 JSON；C验证规则、文案和资源表现。

## 已知问题

当前没有正式规则、内容数据或资产，不应由开发人员自行补写。
